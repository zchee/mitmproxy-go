# mitmproxy-go v0.1.0 release candidate

The first public tag is `v0.1.0-rc.1`, published as a prerelease. Final `v0.1.0` requires an explicit promotion decision and fresh checks of its exact source; release-candidate artifacts are not renamed or reused for it. Public tags use `vMAJOR.MINOR.PATCH` or `vMAJOR.MINOR.PATCH-rc.N`, with positive `N`, no leading zeros and no build metadata; accepted tags are at most 64 bytes.

This first release ships mitmdump, mitmproxy and mitmweb as cross-built Linux, macOS and Windows binaries, not a claim of native acceptance on every target. FreeBSD is build-only and has no release archive. Native macOS/Windows local-mode checks remain manual; native redirectors are installed separately. Starlark replaces Python addons. Timing-sensitive socket/startup cases and the HTTP/3 high-concurrency measurement retain the documented limitations; benchmark correctness is gated separately from throughput. Telemetry first-cause attribution remains inconclusive unless this release's evidence says otherwise. Diagnostics shutdown has a five-second budget, not a guarantee every stalled handler joined.

The `emudhra` and `emudhra_old` options and their revocation-host handling remain [deferred](../compat.md#deferred-differences-against-mitmproxy-1231-and-mitmproxy_rs-01215). The comparison manifest retains 117 names from the raw 119-name inventory by projecting out those two options. The telemetry benchmark comparison ([PR #270](https://github.com/zchee/mitmproxy-go/pull/270)) is not part of this release. No telemetry-on/off measurement series is claimed, and the first-cause diagnosis remains **INCONCLUSIVE**.

Before the first release candidate, selected exported symbols reachable only from tests were removed or unexported; the remaining test-only exported functions are deliberately retained as documented public API.

## Verify and install

The release contains six archives, for Linux, macOS and Windows on amd64 and arm64, each with all three commands. Six matching provenance documents and `SHA256SUMS` complete the 13-file core family. Each core file, including `SHA256SUMS`, has a matching `.sigstore.json` keyless Sigstore signature bundle and GitHub build-provenance attestation. Keep the 13 bundles separate from the core files when verifying the 26-file download.

The source tag is GPG-signed by the approved primary key `D29A27D9FD847A40E42880EAA71DFD3B4DA7A79B`, recorded in the [committed public policy](../../release/signing-policy.asc). A signing subkey is accepted only when it is part of the committed public signing policy. Tag signature checking is a publication gate, not a claim of server-side signed-tag enforcement. The workflow verifies every core file before publication, binding the actual tag, source commit and `.github/workflows/release.yaml` signing identity. It requires the tag's peeled commit and checked-out source to match the approved commit. Publication uses the reviewed `docs/releases/v0.1.0.md` file with `--verify-tag`, adds `--prerelease` only for release candidates, and fails if the notes file is missing, empty or non-regular. Apple code signing and notarization are not provided.

Follow the [verification runbook](../runbooks/release-artifact-verification.md) before extracting an archive. Consistent hashes, source metadata and embedded compiler versions are not a reproducible-build guarantee. Signatures authenticate the expected workflow identity and bytes; attestations state build provenance, not independent source review. Local checker tests are not the production-signer or hosted OIDC acceptance proof.

Supported installation paths are verified archives or an independently pinned clean source checkout. `go install …@version` is not a supported distribution path while `go.mod` carries a replace directive. Ordinary source builds report `0.1.0-dev`; reproducing the plain compiler string requires `GOTOOLCHAIN=go1.27.4` and an empty `GOEXPERIMENT`. No Homebrew, apt, container or automatic-update channel is promised.

## Retained limits

- The [six named socket/startup cases](../runbooks/acceptance-flakes.md#unrepaired-cases) remain unrepaired. PacketTransport, DNS-layer and TLS-layer under-load observations remain open; a green serial rerun is not a repair.
- [HTTP protocol limits](../compat.md#internalproxylayershttplayer) retain the HTTP/3 64 MiB/30-second and 4 MiB/2-second contracts and the HTTP/2 netem 256 MiB transfer, matched 16 MiB windows, 0.8 floor and 30-second measured wait. [Benchmark notes](../bench/README.md) retain the high-concurrency and inconclusive-diagnosis limits.
- [Diagnostics](../../README.md#optional-telemetry-and-diagnostics) have a five-second close budget, not a guarantee that every stalled profiling handler joins. Telemetry queues are bounded and can drop work rather than block the proxy.
- Native [macOS local-mode](../runbooks/local-mode-macos.md), [Windows local-mode](../runbooks/local-mode-windows.md) and [transparent-mode](../runbooks/transparent-mode.md) checks remain operator actions. Cross-building does not establish redirector, driver, process-attribution or terminal acceptance.
- Starlark replaces Python addons. There is no direct cookie-parser fuzz target. Python oracle tooling retains inherited Ruff, mypy and basedpyright findings. The [200×50 console frames](../../testdata/README.md#generated-python-oracle-comparisons) are manually reviewed references, not live Python-regenerated frames.

Long fuzzing remains manual-only with its schedule commented out: 57 package-qualified targets across eight shards, separate from the four required fuzz-smoke jobs. See [fuzzing and benchmarks](../../README.md#fuzzing-and-benchmarks).

## Updates and withdrawal

Verify each update in a new versioned directory before switching the executable path; retain an older verified directory for rollback. Published tags, archives, checksums and signatures are immutable. A withdrawn version receives an explicit notice and a new fixed patch version, not overwritten or deleted bytes. GitHub prerelease marking does not retract a Go module version; Go proxies, the checksum database and downloaded copies can retain it. Follow the [withdrawal procedure](../runbooks/release-artifact-verification.md#withdraw-a-published-version).

`v0.0.0-test.*` proof tags exercise the release checks but never publish a GitHub Release, and their bundles cannot authenticate a differently named public tag.
