## 2. Proxy modes

Spec syntax is `mode[:data][@[host:]port]` (`proxy/mode_specs.py` docstring and `ProxyMode.parse`). The `mode` option is `Sequence[str]`, default `["regular"]`. TCP listeners use `asyncio.start_server`. UDP listeners use `mitmproxy_rs.udp`, dual-stack (`0.0.0.0` plus `::`) when the host is empty (`mode_servers.py:~300-325`).

| Mode | Spec | Transport | Default port | Needs rs |
|---|---|---|---|---|
| regular | `regular` | TCP | 8080 | no |
| transparent | `transparent` | TCP | 8080 | no (uses `platform.original_addr`) |
| upstream | `upstream:[http\|https://]host[:port]` | TCP | 8080 | no |
| reverse | `reverse:SPEC`, default scheme `https`. Schemes: http, https, http3, tls, dtls, tcp, udp, dns, quic | http, tls, tcp: TCP. http3, dtls, udp, quic: UDP. https and dns: both | 8080 (dns: 53) | only for the UDP side |
| socks5 | `socks5` | TCP | 1080 | no |
| dns | `dns` | both | 53 | UDP side |
| wireguard | `wireguard[:PATH]` | UDP | 51820 | yes |
| local | `local[:SPEC]` (validated by `LocalRedirector.describe_spec`) | both | none | yes |
| tun | `tun[:NAME]` (macOS: `utunN`) | both | none | yes |

- `osproxy` is a deprecated alias for `local` and raises `ValueError`. `Http3Mode` is commented out.
- WireGuard keys live in `<confdir>/wireguard.conf` as JSON `{server_key, client_key}`, generated by `mitmproxy_rs.wireguard.genkey()`. The printed client config uses `Address 10.0.0.1/32`, `DNS 10.0.0.53`, `AllowedIPs 0.0.0.0/0` (`mode_servers.py:336-415`).
- `local` is a process-wide singleton. It appends `!<own pid>` to its intercept spec (`mode_servers.py:420-470`).
- Transparent, WireGuard, local and TUN all use `modes.TransparentProxy` as the top layer. The server address comes from the original destination, or from `remote_endpoint` for the rs-backed modes (`mode_servers.py:~196-214`).

## 7. Flow persistence

**Format version.** `FLOW_FORMAT_VERSION = 21` (`version.py`). `io/compat.py` migrates from (0,11)…(3,0) and ints 4…20. The last step, 20→21, changes `tls_version` "QUIC" to "QUICv1" (`compat.py:427-430`).

**Codec.** A file is a plain concatenation of top-level tnetstrings, one flow-state dict each (`io/io.py`).
- Tags: `,` bytes, `;` UTF-8 str, `#` int, `^` float, `!` bool, `~` null, `]` list or tuple, `}` dict.
- The writer encodes dict keys as `;` (`tnetstring.py:_rdumpq`). The module docstring about "surrogate-escaped ASCII keys" is stale. A Go writer must emit `;` for keys. The reader must accept bytes keys, because `compat` handles old files.
- Python `str` values become `;` and `bytes` values become `,`. Enums serialize as `.value`, `Cert` as PEM bytes, `Headers` as a tuple of `(bytes, bytes)` pairs.

**Reader.** `FlowReader.stream()` skips a UTF-8 BOM, then treats a leading `{` as a HAR file (`io/har.py:request_to_flow`). Otherwise it reads the tnetstring stream.

**HAR.** `addons/savehar.py`: `hardump` option, `-` means stdout, a `.zhar` suffix means zlib level 9. Export is implemented. Import goes through `io/har.py`.

**State keys.**
- Base: `version, type, id, error{msg,timestamp}|null, client_conn, server_conn, intercepted, is_replay, marked, metadata, comment, timestamp_created, backup` (`backup` is null unless modified). `type` is the lowercased class name without "Flow".
- Connection: `id, peername, sockname, state(int), transport_protocol, error, tls, certificate_list, alpn, alpn_offers, cipher, cipher_list, tls_version, sni, timestamp_start/_end/_tls_setup`.
  - Client adds `mitmcert` and `proxy_mode` (the spec string).
  - Server adds `address, timestamp_tcp_setup, via`.
- HTTPFlow: base plus `request`, `response|null`, `websocket|null`.
  - Request: `http_version, headers, content, trailers, timestamp_start, timestamp_end, host, port, method, scheme, authority, path`.
  - Response: the same message fields plus `status_code, reason`.
  - WebSocket: `messages` as tuples `(opcode, from_client, content, timestamp, dropped, injected)`, plus `closed_by_client, close_code, close_reason, timestamp_end`.
- TCPFlow and UDPFlow: base plus `messages`, a list of `(from_client, content, timestamp)` tuples.
- DNSFlow: base plus `request` and `response`. Each message has `id, query, op_code, authoritative_answer, truncation, recursion_desired, recursion_available, reserved, response_code, questions[{name,type,class_}], answers, authorities, additionals, timestamp`.

## 8. Filter expressions (`flowfilter.py`)

Grammar: pyparsing `infix_notation` with `!` (not, highest), `&` (and), `|` (or), and `()`. Juxtaposed expressions are implicitly AND-ed. A bare word is `~u`. A regex argument is an unquoted run (excluding `()~'"` and whitespace), or `"…"` or `'…'` with `\` escapes.

Regexes are Python `re`, case-insensitive unless `MITMPROXY_CASE_SENSITIVE_FILTERS=1`. Flags: `~h*` and `~meta` and `~comment` use MULTILINE, `~b*` uses DOTALL.

| Token | Meaning |
|---|---|
| `~q`, `~s` | request without response; has response |
| `~a` | asset content-type (js, css, `image/*`, `font/*`, `application/font*`) |
| `~all` | match all flows |
| `~e` | error |
| `~http`, `~websocket`, `~tcp`, `~udp`, `~dns` | flow type |
| `~marked`, `~marker rex` | marked; marker text matches |
| `~replay`, `~replayq`, `~replays` | replayed flow, replayed request, replayed response |
| `~t`, `~tq`, `~ts rex` | Content-Type header (either, request, response) |
| `~h`, `~hq`, `~hs rex` | headers, matched against the raw `name: value\r\n…` block |
| `~b`, `~bq`, `~bs rex` | body (decoded `get_content`). `~b` also covers WebSocket, TCP and UDP messages and the DNS string form. |
| `~m rex` | method |
| `~d rex` | `request.host` or `pretty_host` |
| `~u rex` | `pretty_url`. For DNS flows, the first question name. |
| `~src`, `~dst rex` | `host:port` of the client peer; of the server address |
| `~meta rex`, `~comment rex` | flow metadata as `k: v` lines; comment |
| `~c INT` | response status code |

`~dns` and `~src/~dst` are accepted on all flow types. `~h`, `~m` and `~c` are HTTP-only.

CA files written to `<confdir>` by `CertStore.create_store` (`certs.py:562-615`), with `basename = "mitmproxy"`:
- `mitmproxy-ca.pem` (PKCS1 private key + CA cert, written under a restrictive umask).
- `mitmproxy-ca.p12` (key + cert, no password).
- `mitmproxy-ca-cert.pem`, `mitmproxy-ca-cert.cer` (same PEM, for Android) and `mitmproxy-ca-cert.p12` (cert only).
- `mitmproxy-dhparam.pem`.

Created only if `mitmproxy-ca.pem` is missing.

CA (`create_ca`, `certs.py:232-281`):
- RSA with `key_size` (default 2048), exponent 65537, signed with SHA-256.
- Subject and issuer are both `CN=mitmproxy, O=mitmproxy`.
- Validity runs from now minus 2 days for 10 years (`CA_EXPIRY`, `CERT_VALIDITY_OFFSET`).
- Extensions: BasicConstraints CA (critical), EKU serverAuth, KeyUsage keyCertSign and cRLSign (critical), SKI.

Leaf (`dummy_cert`, `certs.py:314-403`):
- The leaf **reuses the CA keypair**: `builder.public_key(cacert.public_key())` (`certs.py:339`), and `CertStoreEntry.privatekey = default_privatekey`.
- Validity is 199 days from now minus 2 days.
- CN is set only if shorter than 64 characters. The SAN is critical when the subject is empty. EKU is serverAuth. AKI is copied from the CA's SKI. The leaf has no SKI, because identical CA and leaf SKIs break SChannel.
- Optional CRL distribution point. `tlsconfig.crl_path` is `/mitmproxy-<ca serial>.crl`, served as `application/pkix-crl` (`tlsconfig.py:582-645`).

Store (`CertStore`):
- In-memory dict keyed by CN, SANs, `*` and `(cn, sans)`. Lookup tries asterisk forms such as `www.a.com`, `*.a.com`, `*.com`. FIFO eviction at `STORE_CAP = 100`.
- Custom certs come from the `certs` option (`[domain=]path`).
- SANs are built from the upstream cert's CN, SANs and organization (when `upstream_cert` is on), the client SNI or sockname, and the server address. Duplicates are dropped.

TLS configuration (`tlsconfig.py`):
- Default ciphers: a 26-entry list (`:34-62`), with `@SECLEVEL=0` prepended when the minimum version is below TLS 1.2. Override with `ciphers_client` or `ciphers_server`.
- Versions: min default `TLS1_2`, max default `UNBOUNDED`; choices `UNBOUNDED, SSL3, TLS1, TLS1_1, TLS1_2, TLS1_3`.
- ALPN: the callback prefers the client's ALPN, then the server's, then h2 or http/1.1 (`tlsconfig.py:92-112`). Upstream ALPN mirrors the client's offers (h2 dropped when `http2` is off).
- Client certs: a file, or `<dir>/<sni>.pem` (`:320-330`).
- `ssl_insecure` sets `VERIFY_NONE` (`:285-286`), enables legacy server connect (`:342`), and uses `CERT_NONE` for QUIC (`:433-434`). Otherwise verification uses `ssl_verify_upstream_trusted_ca` or `_confdir`, plus host flags `NO_PARTIAL_WILDCARDS | NEVER_CHECK_SUBJECT` (`:80-82,355`).
- `ignore_hosts`, `allow_hosts`, `tcp_hosts` and `udp_hosts` are enforced in `addons/next_layer.py:84-99,198-258`, not in `tlsconfig.py`.

## 12. Transparent-mode platform support (`platform/`)

| Platform | Mechanism |
|---|---|
| Linux | `getsockopt(SOL_IP, SO_ORIGINAL_DST=80, 16)`, or `SOL_IPV6` with 28 bytes. An IPv4-mapped-IPv6 socket must use the IPv4 call (`linux.py`). |
| macOS and FreeBSD | Runs `sudo -n /sbin/pfctl -s state` and parses the `ESTABLISHED:ESTABLISHED` line (`osx.py`, `pf.py`). Needs passwordless sudo. |
| OpenBSD | `getsockname()` (`openbsd.py`) |
| Windows | Python and `pydivert` (WinDivert): `Resolver`, `TransparentProxy`, `APIServer` on `127.0.0.1:8085` (`windows.py`, 599 lines) |

Windows transparent mode is pure Python. `mitmproxy_windows` serves **local** mode, not this path. Other platforms get `original_addr = None` and an "unsupported" error.

## 13. Scripting and addon loading

- `AddonManager` (`addonmanager.py`): an addon's name is its `.name` attribute or the lowercased class name. Duplicate names raise. `register` fires `load` with a `Loader` (`add_option`, `add_command`), then collects `@command`s and processes deferred options. Addons nest through an `addons` attribute (`traverse`).
- Hook dispatch (`_iter_hooks`): a hook is the method named `event.name` on each addon, called as `func(*event.args())`. Sync and async methods are supported. An `AddonHalt` exception stops the chain.
- `addons/script.py`:
  - `scripts` option, one `Script` per path, loaded with `SourceFileLoader` as `__mitmproxy_script__.<name>`, with the script's directory prepended to `sys.path`.
  - The module itself is the addon, with `name` defaulting to the path.
  - Hot reload: an `os.stat` mtime poll every `ReloadInterval = 1` s. A reload calls `remove`, loads again, then runs `configure` and `running`. If the file disappears, the script is dropped from the option.
  - The `script.run` command replays flows through the script via `eventsequence`.
- `mitmproxy/script/concurrent.py`: `@concurrent` runs a hook in a thread pool, for event hooks only (not `load` or `configure`).
- Deprecated names warn from `register`: `clientconnect`, `clientdisconnect`, `serverconnect`, `serverdisconnect`, `add_log`.

A Go port cannot load Python addons. An equivalent addon API, with a Go hook interface keyed by the section 10 names, is a design decision for the lead.

## What a Go port must reproduce to be mitmproxy-compatible

1. Flow files: concatenated tnetstrings, format version 21, `;` for str keys and values, `,` for bytes, with the section 7 state keys, plus HAR import and the `.zhar` export.
2. Migration of old flow versions through the `compat` chain, or at least a clear rejection message ("cannot read files with flow format version N").
3. CA layout in `~/.mitmproxy`: the five `mitmproxy-ca*` files plus the dhparam file, RSA-2048 CA (CN and O `mitmproxy`, 10-year validity, same extensions).
4. Leaf certificates signed by the CA and sharing the CA keypair (199 days, SAN-driven, 100-entry cache, CRL endpoint).
5. The filter language of section 8: grammar, token set, case-insensitivity, `~h` matching the raw header block.
6. Mode specs `mode[:data][@[host:]port]` for regular, transparent, upstream, reverse, socks5, dns, wireguard, local and tun, with the default ports and transports of section 2.
7. Options: the same names, types and defaults, loaded from `config.yaml`, then `config.yml`, then `--set`.
8. Hook names and event order (section 10). Mind the oddities `error`, `requestheaders`, `responseheaders`, and `HttpErrorHook` naming.
9. Byte-faithful HTTP/1 forwarding: raw header name case and order preserved, and obs-fold handling. HTTP/2 lowercasing is gated by `normalize_outbound_headers`.
10. The mitmweb contract: the 24 routes, the `/updates` WebSocket messages, the XSRF and token auth, and `flow_to_json`, so the committed React build runs unmodified.
